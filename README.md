# Arch Linux Workstation Install

```
LUKS2 (FIDO2 PIN + touch) → Btrfs subvolumes → UKI → systemd-boot → snapper + snap-pac + snap-restore → Sway (Wayland) + Quickshell → AppArmor + Firejail + ufw + hardened sysctl → YubiKey (FIDO2 + OpenPGP)
```

- `install.sh` - live ISO. Partition, encrypt, pacstrap, base config (tty1 runs `login` for your user, so a boot is LUKS, then a YubiKey touch, or the password with the key unplugged), FIDO2 LUKS enrollment, clone this repo, reboot. Prompts: disk, timezone, username, three passwords. Log: `/root/arch-install.log`, copied to `/var/log/arch-install.log` on the installed system. Run from a checkout (`post-install.sh` and `.git` next to it) and it installs that tree instead of cloning `master`.
- `post-install.sh` - installed system, first boot. Bootloader cleanup, snapper limits, pacman hooks (reboot-required flag, orphan report, pacnew list), Intel GPU PMU helper, YubiKey PAM (login, sudo, polkit, lock screen), yay (AUR helper for `slack-desktop`, `zoom`; built with `bin/yay-git`, which falls back to the GitHub AUR mirror when aur.archlinux.org is down - `yay-git slack-desktop zoom` works without yay too), LibreWolf (firejail XDG whitelist + overrides), dotfiles symlinks, GTK/Qt theme (adw-gtk3 + qt6ct), key import, GPG/SSH, an optional SMB share (systemd automount). Resumable via done-markers.

Prerequisite: both YubiKeys provisioned per [YUBIKEY.md](./YUBIKEY.md) (GPG identity on card, the same FIDO2 PIN set on both).

## Step 0 - Flash ISO

Download ISO + `sha256sums.txt` from [archlinux.org/download](https://archlinux.org/download/).

```sh
sha256sum archlinux-x86_64.iso        # Linux
shasum -a 256 archlinux-x86_64.iso    # macOS
```

macOS:

```sh
diskutil list                                                         # find USB by size
diskutil unmountDisk /dev/disk4                                       # unmount, not eject
sudo dd if=archlinux-x86_64.iso of=/dev/rdisk4 bs=4m status=progress  # rdisk = raw node; lowercase 4m
diskutil eject /dev/disk4
```

Linux:

```sh
lsblk
sudo umount /dev/sdb*                                                 # "not mounted" is fine
sudo dd if=archlinux-x86_64.iso of=/dev/sdb bs=4M status=progress oflag=sync   # whole device, not sdb1
sync && sudo eject /dev/sdb
```

- macOS `diskutil list` afterwards shows `FDisk_partition_scheme` + small `0xEF` + free space - normal, write succeeded.
- Won't boot: disable Secure Boot in firmware (stays off - this setup doesn't use it), pick the `UEFI:` entry, not Legacy.

## Step 1 - `install.sh` (live ISO)

Get online first. Wired = automatic. Wi-Fi:

```bash
iwctl device list                       # station name, e.g. wlan0
iwctl station wlan0 scan
iwctl station wlan0 get-networks
iwctl station wlan0 connect "<SSID>"    # prompts passphrase; install.sh copies this profile into the installed system
```

```bash
curl -fsSL https://raw.githubusercontent.com/philipp-bliznuk/arch-btw/master/install.sh -o install.sh
bash install.sh                         # not curl | bash - needs a tty for prompts
```

Prompts, in order: disk (wiped), timezone (`Europe/Berlin`), username, LUKS passphrase, user password, root password (each twice). Summary → type `YES`.

FIDO2 enrollment pauses twice, right after `YES` (disk wiped and LUKS formatted, before pacstrap): `Insert YubiKey #1 ONLY (remove the other), then Enter`, then key #2.

- Exactly one key inserted per pause (`--fido2-device=auto`).
- Each key asks **FIDO2 PIN + touch**. That is the PIN from `ykman fido access change-pin`, not the OpenPGP PIN; the prompt prints the retries left. Three wrong in a row block the applet until replug, eight in total wipe it ([YUBIKEY.md](./YUBIKEY.md#pins)).
- Every boot asks the same PIN + touch (`--fido2-with-client-pin=yes`): laptop and key stolen together stay shut.
- Enrollment failure → retry prompt, not abort.
- Boot with no key inserted → passphrase prompt after 30 s. Keyslot 0 always works.

Flags: `--skip-fido2` (VM), `DEBUG=1 bash install.sh` (trace). Re-run after failure re-wipes the disk.

Baked in: `sgdisk` 2G ESP + LUKS2 remainder; Btrfs `@ @home @snapshots @swap` (`noatime,compress=zstd`); hostname `arch-btw`; RAM-sized hibernation swapfile; systemd HOOKS, two UKIs (`arch-linux.efi`, `arch-linux-lts.efi`; no fallback images: the LTS kernel covers a kernel regression, while both UKIs share `mkinitcpio.conf` and rebuild in the same pacman transaction, so a broken initramfs is the ISO case under Recovery); systemd-boot (`default arch-linux.efi`, `timeout 0` - hold Space at power-on for the menu); ufw on (INPUT DROP, OUTPUT ACCEPT); hardened sysctl; Quad9 DoT; Cloudflare NTS; `earlyoom` (`systemd-oomd` acts only on units that opt in with `ManagedOOMMemoryPressure=`, none do here; earlyoom watches free RAM and swap and SIGTERMs the largest process when both are nearly gone, browser content processes first, sway and quickshell last (`--prefer`/`--avoid` move oom_score by 300): `/etc/default/earlyoom`); Wi-Fi regulatory domain from the timezone's country (`wireless-regdb`, `/etc/conf.d/wireless-regdom`, applied by udev at boot; Intel LAR firmware is `self-managed` and takes the country from the AP, the global domain covers adapters without that); `kernel-modules-hook`; `udisks2` (`udisksctl mount -b /dev/sdX1` as the user, or the launcher's Utils → USB: polkit's default lets an active local session mount, unlock LUKS and power off removable drives without a prompt, nothing automounts; `/etc/polkit-1/rules.d/10-udisks2.rules` puts `loop-setup` and `modify-device` behind an admin auth, since mounting a file one wrote hands root's filesystem parsers to its author); `imv` and `mpv` as the image and video handlers for `xdg-open` (LibreWolf registers neither; Setup → Default apps picks); journald 200M; JetBrainsMono Nerd Font; ucode auto (Intel/AMD); repo cloned to `~/projects/dotfiles`. `btop`, `fastfetch`, `tree`, `go-yq`, `bun` are for the human at the prompt, nothing in the repo calls them. Lid policy: post-install step `lid`.

## Step 2 - `post-install.sh` (first boot)

Unlock, then `Ctrl-Alt-F2` → log in on **TTY2** (TTY1 would `exec sway` once the dotfiles are linked; until step 9 every VT asks the password only).

```bash
~/projects/dotfiles/post-install.sh              # run / resume
~/projects/dotfiles/post-install.sh --list       # step status
~/projects/dotfiles/post-install.sh --redo keys  # force one step
```

## Step 3 - Reboot

Power on → LUKS (YubiKey: FIDO2 PIN + touch; no key: passphrase after 30 s) → TTY1 runs `login` for your user (`getty@tty1` drop-in from `install.sh`; `LOGIN_TIMEOUT 0`, so an unattended prompt does not restart `login` every minute): touch the key while it blinks, or unplug it (or wait the ~29 s) and type the password at `Password:`. The cue says so, because the tty echoes while the token waits: a password typed then shows in clear and is discarded. No autologin, `login` authenticates every time → `zsh/.zprofile` execs Sway. TTY2 keeps the `login:` prompt and stays a shell.

## Security model

| State | Opens it | Notes |
| --- | --- | --- |
| Off, hibernated | YubiKey + FIDO2 PIN + touch, or the LUKS passphrase | Device and key together are not enough. Eight wrong PINs wipe the key's FIDO2 applet, the passphrase remains ([YUBIKEY.md](./YUBIKEY.md#recovery)). |
| Locked session (suspend included) | touch of a plugged YubiKey, or password | Touch without PIN is the walk-away trade-off; `idleSuspend` 3600 s → `suspend-then-hibernate`, `HibernateDelaySec=1h`, so an hour later the next wake is a LUKS unlock. faillock: three wrong passwords within 15 min close the password path for 10 min, the touch path stays open. |
| `login` (any VT), `sudo`, polkit | touch, or password | `pam_u2f` `sufficient` in `/etc/pam.d/login`, `/etc/pam.d/sudo` and `/etc/pam.d/polkit-1` only. A machine left at the prompt with the key plugged in is the same walk-away trade-off as the locked session. Touch without PIN also means code already running as the user can call `sudo` or `pkexec` itself and wait for a touch: the key blinks, nothing on screen says who asked. The jailed browser cannot (`sudo`, `pkexec`, `su` blacklisted, no new privileges); everything else can. faillock does not count the touch path, so a locked-out password still leaves the key. |
| `su`, ssh | password | Neither stack carries `pam_u2f` (`su` has its own, `sshd` uses `system-auth`). `sshd.service` ships with `openssh` and is never enabled; ufw drops inbound anyway. `systemd-ssh-generator` would still start `sshd-unix-local.socket` (AF_UNIX `/run/ssh-unix-local/socket`, local only) on every boot, so `install.sh` masks it. |

Not covered: Secure Boot stays off, so the ESP (systemd-boot, UKIs, `loader/addons`) is unsigned and the boot menu's editor stays on for recovery. Someone with the device reads nothing from the LUKS volume, but can plant a boot change (swapped UKI, a cmdline addon with `systemd.debug_shell=1`) that runs as root inside the decrypted system at the owner's next unlock: evil maid is accepted, not defended. Clipboard history is plaintext on disk (LUKS covers it). gpg-agent caches the on-disk GPG keys' passphrases for 7 days (`max-cache-ttl 604800`, step 17); the card asks its PIN on its own terms. Firejail confines the browser and a few tools (`firecfg --list`), nothing else: another browser gets its stock profile through the hook if `firecfg.config` names it (none of `librewolf.local`'s changes) and runs unconfined if not; the browser also carries AppArmor's `firejail-default` profile through `/etc/firejail/librewolf.local`, and `xdg-dbus-proxy` is what makes the profiles' session-bus filters real (without it firejail allows the whole bus, with only a warning on stderr). The jail talks to the whole `org.freedesktop.portal.Desktop` name, so `xdg-desktop-portal/sway-portals.conf` sets `DynamicLauncher` to `none`: a host app (the firejailed browser is one to the portal) installs launchers through it without a dialog and could overwrite `~/.local/share/applications/librewolf.desktop`, the file the launcher runs. tmux answers OSC 52 writes only (`get-clipboard off`): with the default, any pane's query returns the newest paste buffer without a prompt, and kitty's `read-clipboard-ask` never sees it.

## Desktop shell (Sway + Quickshell)

One Quickshell process owns everything, including the lock screen and the idle ladder (`swaylock` stays installed as the fallback, `swayidle` only bridges logind's Lock and sleep signals). `sway/config` and `tmux/tmux.conf` stay the single source of truth for keybindings - the launcher parses them live into the Keybindings menu (Sway · Tmux · Launcher · Popups), grouping `h/j/k/l` and `1-0` runs into one row and labelling commands from a table in `MenuModel.js`. Helper scripts live in `bin/` (→ `~/.local/bin`, prefix `qs-`, plus `yay-git` and `snap-restore`); launcher rows and panel buttons are data, `core/Commands.qml` turns them into processes (`argv`, `term` = kitty window, `task` = `qs-task` floating window that waits for Enter when done). Every interactive zsh execs into the tmux session `default` (`zsh/.zshrc`; a TTY2 login lands in the same session), except the floating terminal (`$mod+Shift+Return`, started with `NO_TMUX=1`). Floating kitty windows (`qs-float`, `qs-task`) take kitty's own size, 113x27 cells (`initial_window_width/height`, `remember_window_size no`), not a sway `resize set`: whole cells leave no leftover strip for `padding_fill_strategy neighboring_cell` to paint as a ghost status line.

```
quickshell/
├── shell.qml          root: services + panel + launcher, IPC targets
├── core/              Theme Style Icons Util Commands Toggles SwayState Popups System Metrics Player Weather Sun Power Settings Lock (singletons)
├── ui/                Label Glyph Marquee Segment Tooltip PopupCard PopupHost ListRow Chip Field Slider, KeyModel.js (vim keys)
├── panel/             Panel.qml, AudioPopup.qml, MediaPopup.qml, TrayMenu.qml, widgets/ (Workspaces Disk Ram Cpu Gpu NetRate Media Mode Tray
│                      Weather Indicators Dnd NightLight Volume Network Battery KeyboardLayout Clock)
├── launcher/          Launcher.qml Header.qml MenuModel.js AppSearch.js Usage.js
├── notifications/     org.freedesktop.Notifications daemon (popups + history)
├── polkit/            polkit authentication agent
├── osd/               volume / mic / brightness OSD
├── clipboard/         clipboard history (wl-paste watchers → bin/qs-clipboard-capture)
├── lock/              Locker (ext-session-lock + PAM), Surface (per-output lock screen), Idle (screensaver / lock / suspend ladder)
└── background/        wallpaper layer (symlink ~/.local/state/qs/background)
```

Bar: solid 28px (768 - 28 = 740 = 37 kitty rows of 20 px, so one tiled kitty on the laptop panel ends on a cell boundary; a 2560x1440 output leaves 12 px and tiled borders add rows, which kitty paints in the last row's colour), flat `Segment`s, hidden on fullscreen outputs and by the `bar-hidden` toggle; one `PopupCard` open at a time, hosted in a per-output overlay layer (`PopupHost`; not an xdg popup, so keybinds/IPC can open it; clicking outside closes; the card is placed once on open so label changes never move it). Mouse: left-click on Weather/Network/Battery/Clock opens the popup; Dnd and Night light flip on click; Indicators open the launcher's system/toggle section; workspaces switch on click (`$mod+N` is the keyboard path; no wheel switching); slider wheel deltas accumulate to whole 120-unit steps (`Util.wheelSteps`), so a touchpad flick is one step, not a burst; Volume right-click mutes; Night light right-click toggles its automation - those last two are the only segments with a tooltip. Popups carry no on-screen key hints; the key table below is the reference (`Esc`/`q` close everywhere). Resource segments (disk · ram · cpu · gpu · net) and Media/Keyboard sit as plain text, no hover - fed by `core/Metrics` (GPU = `/usr/local/bin/qs-gpu-busy`, an i915-PMU helper built from `bin/src` by `post-install.sh` step `gpu_helper`; falls back to AMD `gpu_busy_percent` or i915 rc6 residency). Tray on every output, icons decoded at device pixels (`sourceSize` × `Screen.devicePixelRatio`); left-click activates, middle-click secondary-activates, right-click (or left-click on menu-only items) opens the item's dbusmenu as a popup card (`panel/TrayMenu.qml`, submenus descend in place; each item's layout is fetched once when it appears so the first open is already filled; `noto-fonts-cjk` supplies the glyphs JetBrainsMono lacks) - quickshell is not in QApplication mode, so native menus are unavailable. Volume segment shows output % (dimmed when muted); the audio popup holds out/mic mute buttons, device pickers (shown when more than one sink/source), a live input level inside the INPUT slider (`PwNodePeakMonitor` opens a capture stream on the default source only while the card is open) and one volume row per app (a browser's per-tab streams collapse into one row and move together). Clock (`Wed 30 14:05:09`), volume %, cpu/ram/gpu % and net rates sit at fixed widths measured from a template string (`Segment.labelTemplate` sized for the typical value, percentages right-aligned so a single digit leaves its gap beside the icon; the clock's follows the day's digit count; `NetRate` pads to three digits and floors at `KiB/s`) so redraws never shift the bar. Icons that swap (volume level, mic, Wi-Fi strength, battery step, weather, play/pause) sit in a slot as wide as the widest glyph of their family (`Segment.iconAlternatives` → `Glyph.alternatives`, measured by ink via `TextMetrics.tightBoundingRect`); the OSD does the same for its icon and sizes its value column from `100%`/`Mic muted`. Media title scrolls once every 10 s when it overflows (`ui/Marquee`; longer when one pass takes longer). Battery state is one `core/Power` singleton shared by every output (one udev listener, one low-battery toast (its last level sits in `PersistentProperties`, so a config reload does not repeat it), one auto-profile write); it reads plugged/charging state from sysfs (`/sys/class/power_supply/AC/online`, `BAT*/status`) and re-reads on `udevadm monitor` power_supply events (plus one settle read 2 s later: the EC reports `Not charging` for ~1 s after a charge-limit write and resumes silently) and on UPower state changes - no polling - so plug/unplug shows instantly instead of after UPower's debounce (UPower still supplies %, time estimates). `qs-toggle nightlight` kills any stray `wlsunset` before starting/after stopping its own so one instance owns gamma on every output. Night light follows sunset/sunrise from `weather.json` (`core/Sun` wakes only at the next sunrise/sunset/midnight; `nightLightAuto` setting); a manual click holds until the next transition, right-click turns the automation off; without a forecast for today (stale file, no network) the automation turns the night light off. Only periodic work in the shell: `core/Metrics` samples each resource on its own timer (net 2 s, cpu 3 s, gpu 5 s, ram 10 s, `df` 5 min) so the bar reads as independent tickers, `qs-weather` refreshes every 15 min, and the Network popup samples rates every 1.5 s while open. Qt timers run on the monotonic clock and freeze across suspend/hibernate, so swayidle's `after-resume` calls `qs-shell shell resume`, which refetches weather, re-reads the clock in `core/Sun` and drops the stale net-rate sample.

Popups open from the keyboard tmux-style: `$mod+o` enters sway mode `popup`, the bar centre shows `POPUP  m media · a audio · n network · b battery · c calendar · w weather` (`panel/widgets/Mode.qml`, fed by `SwayState.mode`), the next key opens the popup and leaves the mode. `resize` mode shows the same way.

Workspaces: `1` and `4` live on the laptop panel, `2` and `3` on the first external output when one is present (sway moves them back out on plug-in, merges everything onto the laptop on unplug). `assign` rules send Slack → 1, kitty → 2, LibreWolf → 3, Zoom → 4; any other workspace is created on the focused output. Caps Lock is a second `$mod` (`caps:super`), so `Caps+N` switches workspaces one-handed. Touchpad: tap to click, `clickfinger` (two fingers right, three middle), `scroll_factor 0.4`. `for_window` floats LibreWolf's picture-in-picture (sticky, follows the workspace) and `xdg-desktop-portal-gtk` dialogs (a separate process without a parent, sway would tile them). The workspace segment shows a dot on workspaces that hold windows (from sway's `representation`). `core/SwayState` runs one `swaymsg -m -r -t subscribe '["window","mode","input"]'` and fans out binding mode, xkb layout and window changes (workspace occupancy refresh on new/close/move/floating only, fullscreen probe) - Quickshell's I3 module only forwards workspace/output events.

Notifications: popups stack top-right on the output that was focused when the first one arrived and stay there until the last is gone (4 visible, the rest wait hidden and start a full countdown when they surface; critical 10 s, others `min(expire, 10 s)`, default 5 s), history of 50 in `notifications.json`, `dnd` toggle. Summary and app name render as plain text; the body is Qt StyledText re-serialised by `notifications/Body.js`: only `b i u s em strong del p br` and `<a href="http(s)://...">` pass as tags, every other `<` becomes `&lt;` (Qt's parser aborts a malformed tag early and resumes mid-text, so a strip that mirrors its grammar can be fed a nested `<img>`; escaping everything unknown cannot), Chromium's page-origin prefix is dropped, links open only for `http(s)`, and every `Label` is `PlainText`, so no sender can make the shell fetch a URL. A `replaces_id` update rewrites the live object without a second `onNotification`, so the card listens for summary/body/image changes, resets its countdown and re-snapshots the history row (once the toast has expired the id is gone from the server, so a later `-r` makes a new toast). The popups live in a `ListModel`, so a toast coming or going leaves the other countdowns alone. The countdown pauses while hovered and resumes with what was left; a pointer parked over the stack holds every toast. sway 1.12 sends no `wl_pointer.enter` to a layer surface mapped under a stationary pointer, so `Stack.qml` maps a 1x1 transparent nudge layer on the first frame after a card appears and unmaps it 100 ms later: each map makes sway rebase the cursor against the drawn toast, which then reads as hovered. Left-click runs the default action (else the first), other buttons dismiss; the `qs-glyph` hint replaces the bell when there is no icon.

Lock and idle: `lock/Locker.qml` holds the `ext-session-lock` (`WlSessionLock`) and two `PamContext`s that run as the user: `qs-lock-password` (`pam_unix`; faillock tallies every wrong password (limits in the security model table); PAM's own notice shows in the status line. The tally file `/run/faillock/$USER` sits in a root-only directory the user-run stack cannot create in, so `lock_pam` installs a tmpfiles rule that creates it at boot, otherwise nothing would count until a `sudo` or polkit auth made the file) and `qs-lock-u2f` (`pam_u2f`, touch only, no PIN; the mappings file is group-readable for that). Both PAM files come from `post-install.sh` step `lock_pam`; without the password one `lock()` falls back to a plain `swaylock` child, and `lock status` reports `fallback` for it and `foreign` for a swaylock the shell did not start (both count as locked for the focus gating below). Engaging: `qs-lock` (sway `$mod+Escape`, also `--locked`), the launcher's `Lock` row, the idle ladder, `swayidle lock 'qs-lock'` on logind's Lock signal (lid closed with an external display attached, step `lid`; `loginctl lock-session`), or `swayidle before-sleep 'qs-lock --sleep'` (`lock sleep` IPC, then polls `lock status` for `"secure":true` for 3 s, then starts swaylock and gives it the last second of a 4 s budget under logind's 5 s delay, then `output * power off`: the kernel thaws every device to write the hibernation image and i915 restores what was lit, so the lock screen would otherwise come back for the seconds the write takes; `swayidle after-resume` runs `output * power on` first). A lock made for sleep starts no touch request until `after-resume`'s `qs-shell -q shell resume`: systemd-sleep freezes the session within the second, the kernel suspends the bus for the snapshot and the token comes back as a new device after a hibernation (the laptop was off), so a request made before sleep could only die, and a touch landing in the few hundred ms before the freeze would have put an unlocked session to sleep; `resume` rescans the token and the touch path starts once udev has made the new node readable. The flag `$XDG_RUNTIME_DIR/qs/locked` is written before the lock is requested and emptied after unlock, so a shell crash, `qs-session restart` or a config reload re-locks on startup (sway keeps the session locked with a red screen in between; `$mod+Escape` re-locks by hand; `FileView` preloads asynchronously even with `blockLoading`, so the check reads `text()`, never `loaded`, before a job was awaited). State lives in `core/Lock` (`locked` = our request; the compositor's confirmation is read from `WlSessionLock.secure` inside `Locker`; never bind on `WlSessionLock.locked`, quickshell never emits its change on unlock). While locked, the launcher, popups and polkit prompt drop keyboard focus and stay closed (sway 1.12 lets exclusive layer surfaces take focus from the lock surface; fixed in sway master). The lock screen: blurred wallpaper, clock, one password field mirrored across outputs (`Esc`/`Ctrl+U` clear), `Enter` submits; with a FIDO token present (`udevadm` `ID_FIDO_TOKEN`, watched while locked) `pam_u2f` runs concurrently and a touch unlocks; a failed attempt (token busy, not readable yet, not enrolled) re-arms after a pause that doubles from 750 ms to 5 s and never stops, the hint reads `YubiKey busy, retrying` meanwhile and `YubiKey not accepted, still retrying` after six instant failures. A pending touch is never aborted: a SIGKILLed `pam_u2f` leaves the token busy with that assertion until its own ~29 s timeout, so a password unlock leaves the child waiting (a lock within that window reuses it) and the child's result is ignored once unlocked. The child's run time is wall clock, so a sleep in between shows up in the log as a run of many hours. The field stays editable during the 2 s rejection delay (`Enter` is ignored until the check ends), and a badge names the xkb layout when it is not the first one. `lockBlank` (10 s, `0` disables) idle seconds while locked power the outputs off and clear the field; the key press that wakes them is swallowed (100 ms, plus that key's auto-repeats while it stays held), and sway's `input added` burst after a VT switch back relights outputs the stored `power off` would keep dark. `qs log` carries `lock:` lines (engaged, u2f attempt/result, password rejected, unlocked by); `lock status` adds `u2fActive`, `u2fAttempts`, `u2fFast`, `sleeping`. Idle ladder (`lock/Idle.qml`, `IdleMonitor`s on `ext-idle-notify`, compositor-timed so suspend cannot skew them): `idleScreensaver` 900 s → `qs-screensaver start` (`cmatrix` in a fullscreen kitty per output, `inhibit_idle none`), `idleLock` 1800 s → lock (which also stops the screensaver), `idleSuspend` 3600 s → `systemctl suspend-then-hibernate`; `0` disables a rung. The `awake` toggle is an `IdleInhibitor` on the wallpaper layer (always mapped; a hidden bar would not count) - `systemd-inhibit --what=idle` never reached swayidle. No `unlock` IPC exists on purpose; `lock status` never includes typed text. `qs-session` runs quickshell under its own supervisor (`QS_DISABLE_CRASH_HANDLER=1`, relaunch unless three deaths within 60 s; `$XDG_RUNTIME_DIR/qs/supervise.pid` names its process group so `stop`/`restart` take supervisor, shell and child processes down together; before relaunching it kills the dead instance's leftover children, since a PAM fork or `wl-paste --watch` still holding the old D-Bus sockets stops the new shell from registering the notification server and the polkit agent, which quickshell never retries).

Polkit: `polkit/Agent.qml` registers a `PolkitAgent` at `/org/qs/PolkitAgent` and shows one card on the focused output (scrim, exclusive keyboard focus, hidden while locked). The message loses polkit's preamble (`Authentication is required to run \`x' as the super user` → `Run x as the super user`), the identity line names the user. PAM runs its modules one after another, so the password field only exists while PAM asks for text; the rest of the time the same box shows a pulsing status with PAM's own words (`Touch the YubiKey, or unplug it and type the password` while `pam_u2f` runs first, about 29 s until the token gives up and the password prompt follows; `Checking` after a submit). When the field is shown it has focus and a click lands in it; while it is hidden a `FocusScope` around the card holds the keyboard, so `Esc` cancels at any point (footer says `Esc cancel` or `Esc cancel · Enter submit`). A touch does authenticate `pkexec`: the `pam-u2f` package relaxes the helper's sandbox (`polkit-agent-helper@.service.d/pam-u2f.conf`, `DeviceAllow=char-hidraw`). Cancelling is not free, though: polkit only closes the helper's socket, PAM runs on, `pam_unix` fails its conversation ~29 s later and faillock counts a strike, the same as a wrong password (`faillock --user $USER` shows them). PAM info lines show below the field only when they arrived with the prompt or during it (faillock's lockout notice); the touch cue from the phase before is not repeated there, since quickshell never clears `supplementaryMessage`. A wrong password shakes the card, borders it red and says `Authentication failed` while polkit starts the next attempt from the touch phase. `qs-shell polkit status` → `{registered, active, responseRequired}`.

Reboot required: `core/System.qml` watches `/run/reboot-required` (written by the pacman hook `zz-reboot-required.hook` for kernels/systemd/glibc/mesa/firmware/…, installed by `post-install.sh` step `pacman_hooks`). No polling, no notification: shows ↻ in Indicators and a yellow dot on `Packages`/`Update`/`Reboot` rows until reboot (`/run` is tmpfs). `kernel-modules-hook` keeps the running kernel's modules through the upgrade (USB storage, exfat, a new dongle still load), so a missing `/usr/lib/modules/$(uname -r)` is not a signal; `linux-modules-cleanup.service` moves the copy to `/usr/lib/modules/.old` on the next boot, tmpfiles deletes it after four weeks.

Packages: `install.sh` turns on `Color`, `VerbosePkgLists` (the package list as a table: name, old → new version, size) and `ILoveCandy` in `/etc/pacman.conf`, nothing else. The mirrorlist is the ISO's copy of `pacman-mirrorlist` (`pacstrap` without `-M`): every mirror on, the Worldwide CDNs first by file order, so pacman tries them first and falls through on failure. The package's own file ships with every `Server` commented out, so each `pacman-mirrorlist` release lands a `mirrorlist.pacnew`; the pacnew row shows it, `r` keeps the list. Measured 2026-10 from a Ukrainian line on `extra.db`, `geo.mirror.pkgbuild.com` 27 MB/s, `fastly.mirror.pkgbuild.com` 19, the best Ukrainian mirror 23 and the rest 8-16, so a `reflector` ranking buys nothing and costs a timer. `qs-pkg update` prints Arch news newer than the newest installed package first (`yay -Pw`; manual interventions are announced there and nowhere else), then `yay -Syu`. The hook `zz-orphans.hook` lists orphans (`pacman -Qdtq`) after every transaction, in the same terminal. yay reads `yay/config.json` (→ `~/.config/yay`, four keys, the rest stay yay's defaults): `sudoloop` keeps the sudo timestamp alive through a long build, so one YubiKey touch covers the install at the end instead of a second prompt blinking at an empty chair; `cleanAfter` deletes the downloaded sources once the package is in (`git clean -fx --exclude '*.pkg.*'` in the clone: 1.1 GB of brave, zoom, slack and 1password archives sat under `~/.cache/yay`, next to 1.8 GB of built packages it would have kept, hence `PKGDEST` on the tmpfs; a downgrade is `snap-restore` or a rebuild from the AUR git history); `removemake` drops make dependencies after the build; `batchinstall` builds everything first and installs in one pacman transaction. Pacnew: `zz-pacnew.hook` runs `pacdiff -o` after any transaction that touched `/etc` and writes the list to `/var/lib/pacnew-pending` (not `/run`: the files outlive a reboot; printed in the upgrade terminal too); `core/System.qml` watches it, `Packages` shows `N pacnew to merge` with the yellow dot (a pending reboot outranks it) and the row `Merge pacnew files` lists them, dimmed when there are none. The row runs `qs-pkg pacdiff`: `pacdiff --sudo` as the user, so each pair opens in `nvim -d` with the user's config through `sudoedit` and only the file moves run as root, then the list is rebuilt. Two edges: a file in a directory the user cannot enter is skipped by pacdiff (the row warns, `sudo pacdiff` merges it), and `sudoedit` refuses a symlinked target such as `/etc/resolv.conf` (→ the resolved stub), so answer `r` there, never `o`, which would replace the link with a file. A `pacdiff` run by hand leaves the list stale until the next transaction. The hook knows the backup files of installed packages, so a `.pacsave` left by a removed package never shows (`qs-pkg remove` uses `-Rns`: none created).

Network share: the `smb` step makes `~/nas` an automount, not a mount. The `.automount` is what boot enables, so nothing waits for the NAS at boot or login; the first `cd ~/nas` mounts (with the NAS unreachable the kernel gives the connect up after 5 s, measured 5-6 s against a dead address and a dropped SYN, 0.3 s when refused: `ls` gets an error, the next access tries again), five idle minutes unmount again (`TimeoutIdleSec=300`), so sleep and lid usually find nothing mounted and the next access starts clean. While something holds it (yazi in the directory) the kernel cifs client reconnects by itself after a Wi-Fi drop or a NAS reboot, `soft` being its default. Measured with the share held open and every packet to the NAS dropped: the first `ls` blocks for three echo intervals before `soft` gives it an error, 187 s at the default `echo_interval=60`, 50 s with `echo_interval=15` (`CIFS: VFS: \\nas has not responded in 45 seconds. Reconnecting...`), hence the option; a further access while the NAS is still gone fails in 10 s, the first one after it is back takes 1 s and the mount is whole again. `LazyUnmount=yes`: `systemctl stop` on that busy, unreachable mount returned in 0.0 s (a shutdown would otherwise wait on it), the automount had it back in 0.1 s. `uid`/`gid` map the files to the user, `file_mode=0644` keeps eza and yazi from painting every file executable. SMB version negotiates (3.1.1 with any current NAS), no `seal`: the LAN is trusted here as for plain HTTP. The password goes `LoadCredential=` → `credentials=%d/...`, so `systemctl cat` and `ps` show a path only. Edges: `stat` on the directory is free (`ls -l ~` does not mount) but the fd walkers behind `Ctrl-T`/`Alt-C` in `~` descend into it and trigger the mount, with the NAS away that thread waits those 5 s; a second share is another `--redo smb` with another path; removal is `systemctl disable --now <unit>.automount`, `systemctl stop <unit>.mount`, `rm` the two units and the credstore file, `daemon-reload`.

Power: kernel and `power-profiles-daemon` defaults, no TLP, no tunables. Measured 2026-10 on the T480 at idle on battery (panel at 36 %, 60 s medians of `BAT1/power_now`; ±0.05 W inside a minute, a few tenths of drift between minutes, so only back-to-back pairs compare). A static screen (one tiled window, nothing redrawing) draws 4.3 W. The knobs were stacked one after another against a 5.3 W baseline (a terminal redrawing, the bar still spinning, next paragraph): `kernel.nmi_watchdog=0`, runtime PM for the Ethernet controller (it does reach D3 with the cable out), for the Wi-Fi card and its root port, for the AHCI controller, USB autosuspend for the SD reader (never idles: the kernel polls it for a card every 2 s, `events_dfl_poll_msecs`) and the Bluetooth radio blocked (its own pair, 5.37 vs 5.39). The medians ran 5.27 to 5.36 with no step down at any knob, so none is worth more than the drift. PCIe ASPM cannot be set at all: the FADT declares no ASPM support and the kernel disables it (`pcie_aspm.policy` refuses writes). The usual checklist buys nothing measurable on this machine; what is on already (`powersave` governor with EPP `power`, `mem_sleep` deep, Wi-Fi power save, `snd_hda_intel power_save=10`, SATA `med_power_with_dipm`) is the kernel's and ppd's doing.

Idle CPU: with nothing changing on screen quickshell sits at 0.5 %, sway at 0, the GPU in rc6 throughout (`/sys/class/drm/card*/gt/gt0/rc6_residency_ms`). The trap, for the next animation: a QML animation inside a hidden window keeps running (item `visible` does not know the window is unmapped), and once a tiled window covers the wallpaper sway stops sending it frame callbacks; the next time it draws under cover (a reload, a wallpaper change) Qt marks that window unexposed and, left with one exposed window, advances every running animation from the bar's vsync, so the bar repaints 60 times a second with nothing new to draw. The polkit card's waiting pulse did that until 2026-10 (12 % quickshell, 8 % sway, GPU out of rc6 27 % of the time, 0.15 to 0.4 W between paired minutes, all on a static screen). Rule: an always-on animation is gated on its window, `running: win.visible && ...`; a `Behavior` only runs on a change and is fine. The lock surface is the same picture from the other side: the bar stays mapped under it and goes unexposed at its next clock tick, so `ui/Marquee` (a long title in Media) also stops while `Lock.locked`, or the lock surface would repaint at 60 Hz for every scroll.

Theme: Catppuccin Mocha, hardcoded in `core/Theme.qml` (named `Theme`, not `Color` - Qt 6.12 ships a `QtQuick/Color` singleton that shadows a singleton of ours by that name). GTK 3/4 share one `gtk/` dir (→ `~/.config/gtk-3.0` and `gtk-4.0`): `gtk.css` sets the libadwaita named colours, `settings.ini` is the fallback; `adw-gtk3-dark` + dark `color-scheme` + fonts go through `gsettings` in `post-install.sh` step `theme`, because GTK3 on Wayland reads `org.gnome.desktop.interface` and ignores `settings.ini` for those keys. Qt apps (incl. `pinentry-qt`) use `qt6ct/` (Fusion, `colors/catppuccin-mocha.conf`, Adwaita Sans) via `QT_QPA_PLATFORMTHEME=qt6ct` from `zsh/.zprofile`; `qs-session` imports it into the systemd user environment so gpg-agent's pinentry gets it too. Quickshell is unaffected: text takes font and colour from `core/Style`/`core/Theme` (through `ui/Label`/`ui/Glyph` almost everywhere) and `shell.qml` starts with `//@ pragma NativeTextRendering`, so every `Text` renders native-hinted.

Launcher: command menu - breadcrumb, frecency (`~/.local/state/qs/launcher-usage.json`, keys namespaced per section), wallpaper thumbnail grid, `=expr` calculator. Root search also covers System, Packages, Capture, Toggle, Setup, Utils and every Keybindings section (rows show a `↳ Section` crumb); name matches rank above keyword matches, then frecency. Apps lists only explicitly installed packages' desktop entries (`bin/qs-apps`), minus `quickshell/apps-hide` (`C--` on a row blacklists it after confirmation); a `Terminal=true` entry (btop) gets a kitty window, since `DesktopEntry.execute()` would start the TUI with no terminal. Setup → Default apps: seven roles (browser, PDF, images, video, audio, text, folders), each a few MIME types with the current handler as subtitle; Enter lists the installed `.desktop` entries claiming them with their `Comment` as subtitle (`bin/qs-defaults`; `NoDisplay` entries count, as in GIO - imv ships `imv` and `imv-dir`, the latter loads the whole folder for next/prev; `Terminal=true` ones stay out, see step `dotfiles`) and a pick runs `xdg-mime default` for the role's types (`~/.config/mimeapps.list`), the dot moves in place. Utils (helper scripts and tools) → USB: removable drives from `lsblk` as state rows - `Mount` / `Open … in yazi` + `Unmount` / `Unlock` / `Lock` / `Power off` - over `udisksctl` (`bin/qs-usb`, mounts under `/run/media/$USER`); `Unlock` runs in a `qs-task` window for the passphrase and mounts what it opened, the other verbs toast the result and the rows redraw; `Power off` shows for drives whose port sysfs flags removable (lsblk `HOTPLUG`; the built-in card reader is on the USB bus too but is not, powered off it stays gone until a reboot), no row means `udisksctl power-off -b` by hand. When the rows do not fit the card (520 px) the list ends mid-row - a row clipped at 55 % is the cue that more sits below the fold - and moving the cursor keeps the neighbouring row peeking past it on both sides; the wallpaper grid folds the same way by rows of thumbnails. The cursor follows the pointer only when the pointer actually moves (more than 1 px), never when the list scrolls under a resting pointer or the card opens beneath it. ## Recovery

- Boots, but broken since an update: `snap-restore` lists the snapshots (it re-runs itself under `sudo`); `snap-restore last` (also the launcher's System → Roll back last update) swaps `@` for the snap-pac `pre` snapshot of the last pacman run, rebuilds both UKIs inside it (kernel on the ESP = modules in the root) and offers the reboot. `snap-restore N` for any other snapshot. The replaced root stays as `@_replaced`, with its disk space, until the next restore deletes it; `snap-restore undo` swaps it back (one level, not a history). Not `snapper rollback` (openSUSE layout).
- The kernel does not boot: hold Space at power-on → systemd-boot menu → `arch-linux-lts.efi`, then `snap-restore last`. Covers a kernel regression only: both UKIs share the initramfs config and rebuild in the same transaction.
- Nothing boots: live ISO → `cryptsetup open /dev/<luks-partition> cryptroot` → `mount -o subvol=@home /dev/mapper/cryptroot /mnt` → `/mnt/<user>/projects/dotfiles/bin/snap-restore --device /dev/mapper/cryptroot list`, then `last` or `N` (same script; `arch-chroot` is on the ISO). `rebuild` instead only rebuilds the UKIs from the current `@` (broken initramfs, root fine; also the way out when a restore's own rebuild failed).
- LUKS header damaged (no keyslot opens, `cryptsetup luksDump` fails): live ISO, `cryptsetup luksHeaderRestore /dev/<luks-partition> --header-backup-file <usb>/luks-header-YYYYMMDD-HHMM.img` from the step 5 USB; keyslots revert to that date.
- Neither key unlocks: boot without key, passphrase (keyslot 0) after 30 s. FIDO2 PIN blocked or applet wiped → [YUBIKEY.md](./YUBIKEY.md#recovery).
- Red screen, no lock prompt (shell died while locked): `$mod+Escape` re-locks (bound `--locked`), or from another VT `WAYLAND_DISPLAY=wayland-1 SWAYSOCK=$(ls /run/user/1000/sway-ipc.*) qs-session restart`, which re-locks from the flag. Lock screen itself broken: from the VT `qs-session stop`, then `WAYLAND_DISPLAY=wayland-1 swaylock` (replaces the abandoned lock), unlock on the sway VT, fix, `qs-session start` (drops the stale flag; `restart` would re-lock).
- Lock prompt refuses a correct password: usually faillock (three wrong tries within 15 min close the password path for 10 min; the status line shows PAM's notice): wait, unlock with the YubiKey, or `faillock --user $USER --reset` as root. A broken `/etc/pam.d/qs-lock-password` → `post-install.sh --redo lock_pam` (when the file is missing `qs-lock` falls back to `swaylock` by itself).
